# 결정이 필요한 사항 (2026-10-11 기준)

개발하면서 임시로 정해 둔 것들이에요. 정해주시면 그대로 반영할게요.
각 항목의 **현재 상태**는 지금 실제로 동작하는 방식이고, **선택지**는 바꿀 수 있는 방향이에요.

---

## A. 업무 규칙

### A1. 초고위험 / 고위험 구분 기준
- **현재 상태**: '결정적 피싱징후'가 있거나, 송금위험도와 AI분석이 모두 '고'면 **초고위험**이에요. 나머지 '위험' 판정은 **고위험**이에요.
- **선택지**: ① 그대로 ② 금액 기준 추가(예: 1,000만원 이상은 초고위험) ③ 유사 사기사례의 유사도 기준 추가

### A2. 사후 확인(수취계좌 AI 재분석) 대상
- **현재 상태**: 지연송금이 승인돼 실행된 건 중 **초고위험은 필수**, 고위험은 선택이에요. 화면에서 둘 다 실행할 수는 있어요.
- **선택지**: ① 그대로 ② 실행된 위험 건은 모두 필수 ③ 금액 기준으로 필수 여부 결정

### A3. 사후 확인에서 '사기 의심'이 나온 뒤의 절차
- **현재 상태**: AI가 "수취은행에 지급정지 요청 + 피해 구제 안내"를 권고하면, 본부가 최종 결과를 '보이스피싱 확정'으로 정하고 종결해요.
  - 지급정지 요청, 고객 연락 같은 후속 조치 단계는 화면에 없어요.
- **선택지**: ① 그대로(종결로 끝) ② 종결 전에 '지급정지 요청'과 '피해구제 안내 완료' 체크 단계 추가

### A4. 고객이 선택하지 않고 떠난 건('고객 선택 대기')
- **현재 상태**: 본부 조치 대기열에서 빼고 별도 탭에 둬요. 본부가 '고객 안내 연락 완료'로 수동 종결해요.
- **선택지**: ① 그대로 ② N시간 뒤 자동 종결 ③ 초고위험이면 본부 조치 대기열에 넣기

### A5. 지연이체 지연 시간
- **현재 상태**: 접수 후 **2시간** 뒤 처리돼요. 고객 화면 문구와 모니터링 기한 표시가 같은 기준을 써요.
  - 2시간이 지나도 본부가 결정하지 않으면 목록에 '지연 해제 시각 지남'(빨강)으로 표시만 하고, 자동으로 송금하지는 않아요.
- **선택지**: ① 2시간 유지 ② 시간 변경 ③ 기한이 지나면 자동 실행 또는 자동 보류

### A6. R01(수취계좌 사기이력) 건수별 배점
- **현재 상태**: 업무 정의("신고 건수에 따라 배점")에 맞춰 **'다건 신고 기준(기본 3건)'과 '다건 배점'을 추가**했어요.
  - 기본값은 1건 이상과 다건 모두 40점이라 SPEC과 똑같이 동작해요.
  - 룰 관리에서 다건 배점을 올리면 바로 반영돼요.
- **결정할 것**: 다건 기준 건수와 배점 값(예: 3건 이상 50점).

### A7. R06·R07 설명과 실제 구현의 차이
- **현재 상태**: 설명에는 '분할 이체'(R06)와 '로그인 위치 급변'(R07)이 들어 있지만, 실제로는 건수와 신규 기기 여부만 봐요. 해당 데이터가 목업에 없어요.
- **선택지**: ① 설명을 구현에 맞게 줄이기 ② 목업 데이터를 추가해 구현하기

### A8. R09~R11(잔액소진율, 신규 수취인 비율, 다수입금 집중)
- **현재 상태**: '준비 중'으로만 표시해요. 잔액, 수취인 이력, 입금 이력 목업 데이터가 필요해요.
- **결정할 것**: 이번 공모전 범위에 넣을지 여부

## B. 운영·보안 (실서비스 전환 시)

### B1. 관리자 로그인·권한
- **현재 상태**: 관리자 페이지에 로그인이 없어요. 담당자 이름은 '구하늘(본부 모니터링 담당)'으로 고정이에요.
- **선택지**: ① 시연용이므로 그대로 ② 간단한 역할 구분(본부 / 영업점 책임자) 추가

### B2. 데이터 보관
- **현재 상태**
  - 실제(로컬) 모드: 룰 설정, 사례 처리, 새 거래 로그가 **서버 메모리에만** 있어서 서버를 다시 켜면 초기화돼요.
  - 데모 모드: **이 브라우저에만** 저장돼요. 다른 사람이나 다른 기기와 공유되지 않아요.
- **선택지**: ① 그대로 ② 로컬은 파일(JSON)에 저장해 재시작 후에도 유지 ③ DB 도입

### B3. 영업점 책임자 면담 입력, 고객 재확인 응답
- **현재 상태**: 시연을 위해 본부 화면에서 대신 입력해요. 버튼에 '(시연용)'이라고 표시돼요.
- **선택지**: ① 그대로 ② 영업점 책임자용 간단한 화면(면담 결과 입력만) 추가

### B4. 수취계좌 이후 거래내역(사후 확인 근거)
- **현재 상태**: 프로토타입이라 **가상으로 만든 예시**예요. 화면에도 그렇게 안내해요.
  - 판정은 규칙 기반이고, AI는 설명문만 써요. 데모 모드에서는 설명문도 규칙 기반 문장이에요.

## C. 시연·데이터

### C1. 데모 숫자와 실제 엔진 숫자의 차이
- **현재 상태**: 데모는 SPEC 5장의 점수를 그대로 보여주고(예: 검찰사칭 90점), 로컬은 실제로 계산해요(같은 입력에 115점 등).
  - **최종 판정(위험·주의·안전)은 같아요.**
- **선택지**: ① 그대로(SPEC 숫자 유지) ② 데모도 실제 엔진 결과 숫자로 맞추기

### C2. 데모에서 바꾼 룰의 효과 범위
- **현재 상태**: 데모 모드에서 룰을 바꾸면 통계와 모의 계산에는 반영되지만, 고객 화면 시연 케이스는 정해진 결과를 그대로 재생해요(서버가 없어서).
- **선택지**: ① 그대로 ② 데모 고객 화면도 바뀐 룰로 다시 계산해 보여주기(시연 케이스 점수가 바뀔 수 있어요)

### C3. 시드(샘플) 데이터 기간
- **현재 상태**: 가상 거래 400건, 위험 리포트 56건, 모니터링 사례 56건을 **2026-08-31 ~ 2026-10-10** 기간으로 다시 만들었어요.
  - 휴무일(추석 등)에는 내방 예약이 잡히지 않아요.
  - 시연 날짜가 더 늦어지면 다시 생성해야 해요: `backend/scripts/generate_seed_data.py`의 `START_DAY`를 바꾸고 실행하면 돼요.
- **은행 휴무일 목록**: 2026년만 있어요(`backend/app/kr_calendar.py`, `frontend/src/utils/branchVisit.ts`). 2027년 시연이면 추가가 필요해요.

### C4. AI 룰 분석 제안의 신뢰도
- **현재 상태**: 과거 거래(정답이 확정된 400건)를 다시 채점해서 더 나은 값을 찾아요.
  - 과적합을 막으려고 현재 값의 ±40% 안에서만 제안하고, 놓친 사기가 늘어나는 제안은 하지 않아요.
  - 다만 데이터가 가상이라 실제 운영에서는 확정 라벨이 충분히 쌓인 뒤에 믿을 수 있어요.

### C5. 데모 리포트 번호
- **현재 상태**: 데모에서 새로 만들어진 리포트는 `RPT-YYYYMMDD-9NN`(9로 시작) 형식이라 시드 데이터와 겹치지 않아요. 실제 모드는 `RPT-YYYYMMDD-001`부터 시작해요.

## D. 이미 반영한 결정(참고)
- 고객 화면에는 1·2·3단계 판단 근거와 리포트를 보여주지 않아요(탐지 로직 노출 방지).
- 위험해도 송금을 완전히 막지 않고 지연이체로 처리해요. 이제 고객이 직접 취소할 수도 있어요.
- 데모·로컬 모두 같은 '시연 케이스' 화면에서 시작해요. 로컬은 고른 케이스의 입력값으로 실제 판정을 해요.
