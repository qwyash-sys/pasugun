# 결정이 필요한 사항 (2026-10-11 기준)

개발하면서 임시로 정해 둔 것들이에요. 정해주시면 그대로 반영할게요.
각 항목의 **현재 상태**는 지금 실제로 동작하는 방식이고, **선택지**는 바꿀 수 있는 방향이에요.

---

## A. 업무 규칙

### A1. 초고위험 / 고위험 구분 기준
- **현재 상태**: '결정적 피싱징후'가 있거나, 송금위험도와 AI분석이 모두 '고'면 **초고위험**이에요. 나머지 '위험' 판정은 **고위험**이에요.
- **선택지**: ① 그대로 ② 금액 기준 추가(예: 1,000만원 이상은 초고위험) ③ 유사 사기사례의 유사도 기준 추가

### A2. 사후 확인(수취계좌 AI 재분석) 대상
- **현재 상태**: 지연송금이 승인돼 실행된 건 중 **초고위험은 필수**, 고위험은 선택이에요. 화면에서 둘 다 실행할 수는 있어요.
- **선택지**: ① 그대로 ② 실행된 위험 건은 모두 필수 ③ 금액 기준으로 필수 여부 결정

### A3. 사후 확인에서 '사기 의심'이 나온 뒤의 절차
- **현재 상태**: AI가 "수취은행에 지급정지 요청 + 피해 구제 안내"를 권고하면, 본부가 최종 결과를 '보이스피싱 확정'으로 정하고 종결해요.
  - 지급정지 요청, 고객 연락 같은 후속 조치 단계는 화면에 없어요.
- **선택지**: ① 그대로(종결로 끝) ② 종결 전에 '지급정지 요청'과 '피해구제 안내 완료' 체크 단계 추가

### A4. 고객이 선택하지 않고 떠난 건('고객 선택 대기')
- **현재 상태**: 본부 조치 대기열에서 빼고 별도 탭에 둬요. 본부가 '고객 안내 연락 완료'로 수동 종결해요.
- **선택지**: ① 그대로 ② N시간 뒤 자동 종결 ③ 초고위험이면 본부 조치 대기열에 넣기

### A5. 지연이체 지연 시간
- **현재 상태**: 접수 후 **2시간** 뒤 처리돼요. 고객 화면 문구와 모니터링 기한 표시가 같은 기준을 써요.
  - 2시간이 지나도 본부가 결정하지 않으면 목록에 '지연 해제 시각 지남'(빨강)으로 표시만 하고, 자동으로 송금하지는 않아요.
- **선택지**: ① 2시간 유지 ② 시간 변경 ③ 기한이 지나면 자동 실행 또는 자동 보류

### A6. R01(수취계좌 사기이력) 건수별 배점
- **현재 상태**: 업무 정의("신고 건수에 따라 배점")에 맞춰 **'다건 신고 기준(기본 3건)'과 '다건 배점'을 추가**했어요.
  - 기본값은 1건 이상과 다건 모두 40점이라 SPEC과 똑같이 동작해요.
  - 룰 관리에서 다건 배점을 올리면 바로 반영돼요.
- **결정할 것**: 다건 기준 건수와 배점 값(예: 3건 이상 50점).

### A7. RAG 매칭만으로 '위험' 강제 판정되는 범위
- **현재 상태**: 고객 설명과 가장 비슷한 사례가 매칭 기준(0.60) 이상이고, 그 사례에 결정적 피싱 징후 태그(안전계좌·원격제어앱·화면유지요구)가 있으면 점수와 관계없이 '위험'이에요.
  고객이 실제로 그 말을 했는지는 따로 보지 않아요(예: 검찰 사칭 사례와 매칭되면 '안전계좌'를 말하지 않아도 위험).
- **선택지**: ① 그대로(보수적으로 막기) ② 강한 매칭(0.80 이상)일 때만 강제 ③ 고객 발화에 해당 징후 표현이 실제로 있을 때만 강제
- **참고**: 사례집 관리의 사례 등록 화면에서 결정적 징후는 체크박스로 따로 고르게 바꿨어요(태그 띄어쓰기 오타로 강제 판정이 빠지는 문제 방지).

## B. 운영·보안 (실서비스 전환 시)

### B1. 관리자 로그인·권한
- **현재 상태**: 관리자 페이지에 로그인이 없어요. 담당자 이름은 '구하늘(본부 모니터링 담당)'으로 고정이에요.
- **선택지**: ① 시연용이므로 그대로 ② 간단한 역할 구분(본부 / 영업점 책임자) 추가

### B2. 데이터 보관
- **현재 상태**
  - 실제(로컬) 모드: 룰 설정, 사례 처리, 새 거래 로그가 **서버 메모리에만** 있어서 서버를 다시 켜면 초기화돼요.
  - 데모 모드: **이 브라우저에만** 저장돼요. 다른 사람이나 다른 기기와 공유되지 않아요.
- **선택지**: ① 그대로 ② 로컬은 파일(JSON)에 저장해 재시작 후에도 유지 ③ DB 도입

### B4. 수취계좌 이후 거래내역(사후 확인 근거)
- 현재: 개발 모드와 데모 모드 모두 **가상 거래내역 생성기**로 만들어요(`backend/app/payee_activity.py`, `frontend/src/admin/engine/postcheck.ts`).
  - 개발 모드에서도 '수취계좌 AI 재분석'을 누르면 동작하고, 서버의 실제 AI가 설명문을 써요.
  - 데모는 같은 규칙에 규칙 기반 설명문만 써요.
- 생성기가 수취계좌의 목업 정보(사기 신고 이력·개설일)를 보고 사기형 흐름(분산 이체·ATM 출금)이나 정상형 흐름(공과금·보유)을 만들어요.
  - 같은 사례는 항상 같은 내역이 나와요.
- 한계: 송금 직후 바로 재분석해도 '그 뒤 48시간 동안의 거래'를 미리 만들어 보여줘요(시간 경과를 가정한 시연).
  - 실서비스에서는 수취은행 연계로 실제 내역을 받아 시간이 지난 뒤 분석해요.
- 선택지: ① 그대로 ② 개발 모드에서는 '현재 시각까지 발생한 거래만' 보여주고 시간을 앞당기는 시연 버튼 추가

## C. 시연·데이터

### C2. 데모에서 바꾼 룰의 효과 범위
- **현재 상태**: 데모 모드에서 룰을 바꾸면 통계와 모의 계산에는 반영되지만, 고객 화면 시연 케이스는 정해진 결과를 그대로 재생해요(서버가 없어서).
- **선택지**: ① 그대로 ② 데모 고객 화면도 바뀐 룰로 다시 계산해 보여주기(시연 케이스 점수가 바뀔 수 있어요)

### C3. 시드(샘플) 데이터 기간
- **현재 상태**: 가상 거래 400건, 위험 리포트 56건, 모니터링 사례 56건을 **2026-08-31 ~ 2026-10-10** 기간으로 다시 만들었어요.
  - 휴무일(추석 등)에는 내방 예약이 잡히지 않아요.
  - 시연 날짜가 더 늦어지면 다시 생성해야 해요: `backend/scripts/generate_seed_data.py`의 `START_DAY`를 바꾸고 실행하면 돼요.
- **은행 휴무일 목록**: 2026년만 있어요(`backend/app/kr_calendar.py`, `frontend/src/utils/branchVisit.ts`). 2027년 시연이면 추가가 필요해요.

### C4. AI 룰 분석 제안의 신뢰도
- **현재 상태**: 과거 거래(정답이 확정된 400건)를 다시 채점해서 더 나은 값을 찾아요.
  - 과적합을 막으려고 현재 값의 ±40% 안에서만 제안하고, 놓친 사기가 늘어나는 제안은 하지 않아요.
  - 다만 데이터가 가상이라 실제 운영에서는 확정 라벨이 충분히 쌓인 뒤에 믿을 수 있어요.

### C5. 데모 리포트 번호
- **현재 상태**: 데모에서 새로 만들어진 리포트는 `RPT-YYYYMMDD-9NN`(9로 시작) 형식이라 시드 데이터와 겹치지 않아요. 실제 모드는 `RPT-YYYYMMDD-001`부터 시작해요.

### C6. 사례집(RAG) 관리 — 데모 모드의 유사도 계산 범위
- **현재 상태**: 관리자 페이지에 **'사례집 관리'** 메뉴를 추가했어요(사례 목록·유형별 탐지 현황, 유사도 시험, 검증 문장 점검, 변경 이력, 사례 등록·수정·검색 중지).
  로컬 모드는 등록·수정 즉시 실제 SBERT + FAISS 색인을 다시 만들어 고객 화면 판정에도 바로 반영돼요.
  데모 모드는 브라우저에서 문장을 임베딩할 수 없어서 **검증 문장 27개만 실제 엔진으로 미리 계산한 결과**를 보여줘요(`backend/scripts/generate_rag_demo.py`).
  검색 중지는 데모에서도 정확히 반영되지만, 데모에서 새로 등록·수정한 사례의 유사도는 계산되지 않아요.
- **선택지**: ① 그대로(시연은 로컬 모드로 '신규 수법 등록 → 바로 탐지'를 보여주기) ② 데모에 '투자 리딩방' 같은 신규 수법 예시를 미리 계산해 넣기
- **참고**: 시드 거래의 사기 발화는 모두 기존 사례로 잡혀서 '유형별 탐지 현황'이 전부 100%예요. '사례 보강 필요'를 시연하려면 기존 사례에 없는 수법(예: 투자 리딩방) 거래를 시드에 넣어야 해요.
- **저장**: 룰 설정처럼 서버 메모리에 저장돼 재시작하면 기본 12건으로 돌아가요(B2와 같이 결정).

## D. 이미 반영한 결정(참고)

- **2026-10-15 사례집 위험신호 정리**: 사례의 '위험신호'는 결정적 피싱 징후(안전계좌·원격제어앱·화면유지요구)만 남기고 일반 태그는 모두 지웠어요. AI 룰 분석의 새 룰 후보는 태그 대신 사기 유형으로 연결해요. 검증 문장 결과와 데모 시연 케이스 판정·점수는 바뀌지 않았어요.
- (2026-10-14) R06에 분할 재시도, R07에 접속 위치 급변 목업 데이터 추가. R09 잔액소진율 · R10 신규 수취인 급증 · R11 다수입금 집중 구현(목업: 고객 잔액, 최근 7일 새 수취인 수, 수취계좌 24시간 입금인 수). SPEC 시연 5케이스 판정은 그대로예요.
- (2026-10-14) 영업점 책임자 화면(관리자 페이지 > 영업점 책임자, 파랑)과 고객 재확인 응답 화면(고객 앱 알림)을 만들고, 본부 화면의 '대신 입력(시연용)'을 없앴어요. 입력 창 머리표: 본부=초록 '본부 조치', 책임자=파랑 '영업점 책임자'.
- (2026-10-14) 데모 시연 케이스의 점수·판정·리포트는 개발 모드 엔진으로 계산한 값을 써요(`backend/scripts/generate_demo_cases.py`). 예: 검찰사칭 송금위험 155점(새 룰 포함), 판정은 동일.
- (2026-10-14 결정) 송금을 취소한 뒤 영업점 상담을 예약하면 사례를 다시 열어 '영업점 내방'으로 진행해요(담당 책임자 메일 포함). 고객이 112·1332 안내를 누르면 모니터링에 파란 알약으로 표시돼요.

- 고객 화면에는 1·2·3단계 판단 근거와 리포트를 보여주지 않아요(탐지 로직 노출 방지).
